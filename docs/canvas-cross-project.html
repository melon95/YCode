跨项目画布

画布从「当前项目的会话」改成「任意项目的会话」。同一个窗口里最多 4 格，每一格可以来自不同项目。窗格必须一眼分清「这是哪个项目的 agent」，右侧的文件、Git、Todo 面板跟随焦点窗格的项目切换。

要解决的问题

  • 同时盯多个项目的 agent，现在只能来回切项目，画布整体被换掉。
  • 混放之后，4 格里哪格属于哪个项目、哪格在等输入，必须一眼可辨。

成功标准

  • 侧栏点任意项目的会话，只聚焦或并排新开一格，不再切换整块画布。
  • 不靠颜色也能认出项目（名称 + 首字母图标）。
  • 右侧面板始终和焦点窗格的项目一致，且有明确标识。

3　侧栏点击与窗格操作不再切项目

现有行为是跨项目点击会话就调 selectProject，整块画布被换掉。改成：画布永远是同一块，点击只改变「哪些会话在画布上」。

操作现在方案 A
点击别的项目的会话（未在画布）切换项目，换成该项目的画布有空位就并排新开一格，满 4 格替换焦点格。画布其余窗格不动
点击已在画布上的会话同项目内聚焦聚焦该格，右侧面板跟随切换
项目行「+」新建会话先切项目再新建打开新建会话选择器，项目下拉框默认选该项目（见 §4）；新会话进画布，不切换其他窗格
窗格头右键 / 菜单关闭窗格新增「在侧栏中定位」「仅看此项目」（见 §5）
关闭窗格reflow 布局不变；该会话进程继续在后台运行

5　不靠颜色识别无障碍

为什么不能只靠项目色

  • 项目色之间的区分，对红绿色弱不可靠；徽章必带项目名和首字母图标。
  • 徽章白字在项目色上的对比度需 ≥ 4.5:1。上图 4 个色里，琥珀色 #d98a1f 偏低，实现时需加深或改用深色字，以验证器为准。
  • 项目色超过 4 个时会重复，所以颜色只做辅助，名称才是身份。

键盘与读屏

  • ⌘1–⌘4 继续是按槽位聚焦，不变。
  • 窗格的无障碍标签：「项目 api-gateway，Codex，会话：限流中间件，等待输入」。
  • 焦点变化时读出「焦点：api-gateway」，因为右侧面板内容随之改变。

7　待确认的取舍

问题建议理由
画布快照是否仍按项目保存改成全局一份；每个会话仍属于自己的项目混放后「按项目的画布」没有意义，保留两套会让恢复逻辑变复杂
切换项目（侧栏项目行/概览）的含义只决定侧栏展开和「新建会话」的默认项目，不动画布项目选择和画布解耦，是整个方案的前提
画布上没有任何会话仍显示 agent 选择器，项目下拉框默认最近使用的项目沿用现有空状态，改动最小
项目色来源按项目 id 哈希自动分配，用户可在项目右键菜单里改零配置可用，且颜色稳定不随排序变化
只混放同项目会话时徽章照常显示避免「有时有、有时无」导致窗格头高度和布局跳动

定稿后再进入实现：按之前的约定，窗格阴影与描边在 AppKit 层（YCodeCanvasShadow / YCodeCanvasPane），徽章属于 SwiftUI 窗格头内容；强调色一律用 ycodeAccent。

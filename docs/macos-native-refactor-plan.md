日期：2026-09-14
状态：执行中；M0.1–M0.4、M1.1–M1.4、M2.1–M2.5、M3.1–M3.5、M4.1–M4.3、M4.5、M4.6、M5.1、M5.2 已通过；M4.4 为部分通过（协议与安装管理通过，LS.3–LS.7 编辑器内语义交互转入后置范围）。

## 1. 目标与范围

将当前 Tauri + React/TypeScript + Rust 应用重写为 **Swift + SwiftUI/AppKit 的 macOS 应用**。保留当前可用功能和已有数据，worktree 相关能力暂缓。

- 只支持 macOS；最低版本暂定 macOS 14，最终在原生组件验证后锁定。
- 自有应用、服务和辅助程序使用 Swift；界面、终端、编辑器均原生渲染，不以 WebView 承载原有前端。
- 可以使用系统框架和原生开源组件；“原生”不等于从头手写终端模拟器、数据库或文本排版引擎。
- 保留 Claude Code、Codex、Gemini、自定义 CLI 的接入方式。外部 CLI 自身所需的 Node 等运行环境不属于 YCode 的应用运行时。
- **暂缓 worktree 创建、隔离开关、专属分支、合并和自动清理**。首版新会话直接在项目目录运行；不增加新的工作目录隔离方案。
- 现有 worktree 记录和磁盘目录保留；首版不主动恢复这些隔离会话，不把它们静默改为主目录会话，也不删除其分支或目录。普通会话恢复照常迁移。
- 普通 Git 分支操作、提交、diff 和检查点仍保留，不能因暂缓 worktree 一并删掉。
- 本次不切换到 pi，不增加自研模型对话、权限引擎等新产品范围。

基准是当前代码。`pi-implementation-plan.md`、`ycode-feature-spec.md` 中删除 Agent 管理、编辑能力和 LSP 的方案不适用于本次重构。

## 3. 技术方案

| 层次 | 方案 | 说明 |
|---|---|---|
| 窗口与普通界面 | SwiftUI | 三栏工作区、侧栏、工具栏、设置、命令菜单 |
| 桌面复杂交互 | AppKit | 终端、代码编辑、精细焦点管理、窗口与拖拽桥接 |
| 终端渲染 | 优先验证 SwiftTerm | 原生终端模拟器；先验证真实 CLI，再锁定依赖版本 |
| 进程与 PTY | 独立 Swift 服务 + macOS/POSIX 接口 | 生命周期独立于视图，支持后台会话、输入、尺寸、信号和退出回收 |
| 编辑器 | TextKit/AppKit；评估 STTextView | 原生文本组件只是底座，语法高亮、标签、保存冲突和 LSP 需独立迁移 |
| 历史解析、用量统计 | Swift | 按现有 Claude/Codex JSONL 格式与测试样本重写 |
| 数据与配置 | SQLite + JSON | 延续数据结构与 ID，不同时引入 SwiftData 数据模型迁移 |
| Git、文件和目录监听 | Swift 服务 | Git 使用参数化进程调用；文件系统操作与监听由系统接口完成 |
| LSP / MCP | Swift 协议与进程服务 | 延续现有协议能力和配置集成，辅助程序也改为 Swift |
| 系统通知、深链、剪贴板 | macOS 系统框架 | 替代 Tauri 插件，保留行为与入口 |
| 更新与发布 | 原生更新方案 + macOS 签名发布 | 单列迁移更新源、验证签名、失败恢复，不能直接复用 Tauri 更新插件 |

组件依据：[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) 提供 macOS 终端视图及本地 PTY 集成；[STTextView](https://github.com/krzyzanowskim/STTextView) 提供 TextKit 2 文本组件。二者是候选底座，不代表已经验证了 YCode 的功能兼容性。

状态分为三层：

1. **应用级**：配置、数据库、会话进程池、历史索引、通知、集成服务。
2. **窗口级**：当前项目、画布布局、面板可见性、文件标签和焦点。
3. **视图级**：搜索文本、临时选择、弹出菜单等短暂状态。

核心约束：关闭终端面板不等于杀进程；重新显示不应重复启动 Agent。多个窗口共享服务，不能各自创建一份进程池。

建议目录：

```text
macos/
  YCodeApp/                 应用入口、窗口与系统菜单
  Features/
    Workspace/             项目、侧栏、画布、多窗口
    Sessions/              会话与 Agent 管理
    Terminal/              原生终端视图与交互
    History/               搜索、历史展示、用量
    Files/                 文件树、预览、编辑器
    Changes/               Git、diff、检查点
    Todos/                 待办
    Settings/              设置与集成入口
  Core/
    Persistence/           SQLite、配置、迁移
    Processes/             PTY、进程池、环境变量
    Introspection/         Claude/Codex 解析
    Git/                   Git 操作与检查点
    LanguageServices/      LSP 与安装管理
    Integrations/          MCP、通知 hook、CLI 协议
  Helpers/                 ycode、ycode-mcp、ycode-notify
  Tests/                   核心测试、兼容样本、界面验收
```

## 4. 功能对照与验收重点

以下全部纳入首版；只有明确列出的 worktree 能力后置。

| 模块 | 要保留的功能 | 关键验收 |
|---|---|---|
| 项目 | 添加、删除、切换、排序、分组、总览、最近项目 | 重启后的项目和顺序正确；删除语义与旧版一致 |
| Agent | 内置目录、自定义命令、参数、环境变量、图标、历史解析器 | 登录 shell、PATH、变量展开及代理设置一致 |
| 会话 | 新建、停止、重启、恢复、重命名、归档、状态、关注收件箱 | 恢复使用原始 Agent 会话标识；后台状态不会随焦点失真 |
| 画布 | 单列、堆叠、多列、2×2、主副布局，面板开关与尺寸 | 切布局不丢进程和输出，快捷键指向正确面板 |
| 多窗口 | 项目独立窗口、激活已有窗口、关闭后释放占用 | 不重复启动会话；窗口切换和关闭保持状态一致 |
| 终端 | 真 PTY、回滚缓冲、搜索、复制粘贴、链接、路径跳转、动态字号 | 中文输入、Emoji、ANSI、全屏 TUI、连续输出与缩放均可用 |
| 辅助终端 | 项目 shell、上下左右分屏、拖拽调尺寸、单独关闭 | 关闭一个 shell 不影响其他 shell 或 Agent |
| 历史 | Claude/Codex 扫描、全文搜索、展示、恢复、增量刷新 | 老 JSONL 可读；坏行不使整体加载失败；不重复计入记录 |
| 用量 | 会话、项目、模型、日期维度统计 | 用相同样本对比旧版数值与缺失值处理 |
| 文件 | 文件树、新建、重命名、删除、外部编辑器、Finder 定位 | 相对路径与中文路径正确；工作目录切换不串文件 |
| 编辑器 | 标签与预览标签、编辑保存、未保存提示、外部变化处理、语法高亮 | 切标签保留未保存内容；不静默覆盖外部改动 |
| 内容预览 | 图片、Markdown、SVG 及源码/预览切换 | 原生预览逐项比对现有内容能力，不用 WebView 回退冒充原生 |
| LSP | 安装卸载、进度、文档同步、语义高亮、定义跳转 | 真实语言服务器完成打开→修改→跳转→关闭流程 |
| Git | 状态、并排 diff、逐块操作、暂存、取消暂存、丢弃、提交 | 覆盖未跟踪文件、重命名、二进制文件与操作失败 |
| 普通分支 | 分支列表、切换、fetch、pull、push | 保留错误信息与用户选择，不因移除 worktree 一并隐藏 |
| 检查点 | 初始及轮次快照、列表、逐轮差异审阅 | 在普通项目目录验证，Git 对象与数据库元信息一致 |
| 待办 | 创建、改名、状态流转、时间戳、删除、排序 | 界面与 MCP 修改彼此实时可见 |
| MCP / hooks | 安装状态、安装卸载、Todo MCP、Claude/Codex 通知链 | 保留用户已有配置；辅助程序可独立执行并正确路由 |
| 系统入口 | `ycode .`、CLI 安装卸载、深链、通知、快捷键、命令面板 | 已启动/未启动、多窗口两类情况均能打开正确项目 |
| 设置 | 中英文、明暗/系统主题、旧主题兼容、字号、通知、代理、面板与启动选项 | 保存/取消/恢复默认语义一致，未知配置不被静默清空 |
| 发布 | 版本信息、检查更新、升级、窗口状态恢复 | 从旧版升级的数据兼容；签名、失败恢复和回退可验证 |

## 5. 实施步骤与预期结果

每个编号是一项独立验收任务，不能仅以“代码写完”或“编译通过”标记完成。下列结果均为**待实现目标**，不是已经验证的事实。

执行规则：

- 每步开始前确定输入样本和预期结果，完成后记录实际结果及证据路径。
- 状态统一为：未开始、实现中、待验收、通过、阻塞。所有步骤初始均为“未开始”。
- 依赖步骤通过后，才能验收依赖它的下一步；同阶段内没有依赖的工作可独立推进。
- 前一步未通过时，修复后重验，不能把缺口藏到下一阶段。变更验收标准必须记录原因，不能为通过验收事后降低要求。
- 每阶段都交付可运行版本或验证程序，以及对应验收报告。M0 是验证程序，M1 起是原生应用。
- 不依赖代码进度的外部依赖（证书、开发者账号、密钥、托管服务）必须在首个阶段启动申请，不得作为末阶段步骤的内部环节。此类依赖缺失时，应把受影响步骤拆成"可自持的工程部分"与"依赖外部条件的部分"，前者照常推进验收，不得让整条收尾链停在一项行政事项上。

### M2：Agent 与终端完整工作流

**阶段结束时：** 可在原生应用中日常运行多个 Agent，切换项目、布局和窗口不会丢失会话。

前置：M1 通过；真实 hook 通知在 M3 接通，本阶段先验证进程状态和事件接收逻辑。

| 步骤 | 工作与交付物 | 预期结果 | 验收方法与通过条件 |
|---|---|---|---|
| M2.1 | Agent 目录、自定义配置与启动环境服务 | Claude/Codex、Gemini 配置和自定义命令均可启动；命令、参数、环境变量、登录 shell、PATH 与代理按配置生效 | 用真实已安装 CLI 和可控环境回显程序验证；参数边界、空格路径、变量覆盖顺序符合基线；程序不存在时给出明确错误；敏感值不写入日志或展开后回存配置 |
| M2.2 | 会话进程池与生命周期管理 | 新建只启动一次；停止后进程退出；重启只有一个新进程；恢复进入原有普通会话；改名与归档可持久化 | 对真实 Claude/Codex 验证会话 ID 和历史上下文；对测试进程验证退出码、信号、失败和子进程回收；归档/关闭的确认及取消行为与清单一致 |
| M2.3 | 完整终端交互与画布布局 | 五种布局、面板开关、尺寸变化、搜索、链接、路径跳转、粘贴及字号均可使用 | 4 个带不同标识的会话持续输出，依次切换所有布局并重复开关面板 20 次；没有串输入、重复进程或丢失保留范围内的输出；链接打开正确目标 |

## 6. 数据迁移约束

- 从实际后端 `ProjectDirs` 解析规则确认数据库/配置路径，不能只信 README 或 Tauri 前端显示的应用目录。
- 保留项目/会话 ID、Agent 恢复标识、归档状态、待办排序和时间戳、LSP 安装记录、检查点元信息。
- SQLite 的 WAL 中可能有最新记录，使用一致性备份，不能只复制 `ycode.db` 单文件。
- 配置保留未知字段、用户自定义 Agent 和未展开的变量，不能把展开后的环境变量写回配置。
- 原有 worktree 元信息照原样保留；默认不搬动目录，不进行删除、合并或恢复操作。
- Claude/Codex JSONL 保持在原目录，只读扫描；新应用不复制维护第二份对话内容。
- WebView localStorage 内的项目顺序、最近项目和文件树宽度单独设计导出/导入；窗口状态也单列迁移，不能只迁 SQLite。
- 开发阶段原生版使用独立数据目录和应用标识；发布切换前再验证正式标识、深链、辅助程序路径与数据归属。
- 旧版与原生版同时启动的写入冲突必须有明确处理；首次正式切换先关闭旧版，再做最终备份和导入。
- **本地自用期为单向规则**：切换后旧版不再启动，旧 app 移入快照目录而非留在 `/Applications`。需要回退时走 `cutover.sh rollback --local`，由脚本恢复旧 app 与切换前数据并保留期间新增的原生数据；不依赖"记得不要打开旧版"这类人工约定。

## 7. 验收方式

1. **核心行为**：用相同输入样本比较旧版和 Swift 的解析、统计、配置、状态变化结果。
2. **数据兼容**：覆盖当前及旧 schema、WAL、空库、异常中断、未知配置字段、失败回退。
3. **真实运行**：实际 CLI、实际 PTY、实际 LSP、实际原生窗口；构建成功不能代替功能验收。
4. **文件与 Git**：在临时项目覆盖保存冲突、提交、逐块操作、分支和检查点，不拿用户工作目录做破坏性测试。
5. **性能与稳定性**：同机器、同 CLI 版本、同样本比较启动、空闲资源、终端输出、搜索与编辑响应。

01

现状诊断

「像 demo」不是一句观感，它有七个可以指到代码行的成因。每一条都不是没做完， 而是做完了但摆错了位置 —— 所以修它不需要动功能。

问题 01

主角不在主位

终端是 projectDetail 里 VStack 的最后一项。它上面压着会话标题、 agentProfile、PID、Agent 会话 ID，和「停止 / 恢复重启 / 重命名 / 归档」四个按钮。 终端只拿到剩下的空间。

YCodeNativeApp.swift:511-544
对策 终端占满整个内容区。上面那些全部移出主区：进程信息→状态栏， 会话动作→窗格头右键菜单，会话 ID→「会话信息」浮层。
问题 02

两列侧栏，一棵两层树

NavigationSplitView 三列：项目一列（min 210）、会话一列、详情一列。 近 460 px 的横向空间只承载了「项目 → 会话」这一层父子关系，而项目通常只有个位数。

YCodeNativeApp.swift:219-225, 422-486
对策 合成一列 238 px：项目是可折叠的组标题，会话是组里的行。 省出的 220 px 给终端。
问题 03

工具栏是功能抽屉

七个按钮：加项目、新会话、独立窗口、删项目、上移、下移、注意力。 「上移项目 / 下移项目 / 删除项目」是侧栏的右键菜单内容，把它们放进窗口工具栏， 是最典型的 demo 症状 —— 有个功能就给个按钮。

YCodeNativeApp.swift:591-633
对策 工具栏只留跨会话的东西：布局、检查器、注意力、⌘K。 项目管理整体进侧栏右键菜单。
问题 04

状态语言不成体系

七种运行态（running / starting / exited / signaled / recoverable / pendingApproval / waitingInput） 散落在三处渲染：侧栏 badge、画布 pane 头的 Circle()、详情页标题行。 三处写法都不同，颜色是裸的 .green / .orange / .red。

sessionStatusBadge() :679 与 terminalPane() :137
对策 收敛成两个：运行中 / 等你。 会话都能 resume，「已退出」「可恢复」不是用户要判断的事。 一处定义，侧栏、窗格头、收件箱三处复用同一个点。
问题 05

内部状态外泄到界面

项目页上直接铺着「File Tree Width 180 px (active since M4.1)」「隔离开关记录：保留未启用」 和数据目录绝对路径；菜单栏还挂着一个 Migration 菜单。 M4.1 是迁移计划的步骤编号，用户没有上下文。

YCodeNativeApp.swift:562, 569 · 已记为 L-04
对策 这些是诊断信息，不是产品信息。 统一收进「设置 › 关于 › 诊断」，一键复制给 issue。Migration 菜单不进正式包。
问题 06

面板没有固定位置

五个面板由 openPanels: Set 驱动，开几个就在画布右边竖着堆几个， 共用一个 fileTreeWidth。今天开两个、明天开三个，布局每次都不一样， 用户无法形成肌肉记忆。而且这五个不是一类东西：终端是画布本身， 历史是过去的会话 —— 只有文件 / 变更 / 待办是「当前工作区的切面」。

TerminalWorkspaceView.swift:14-25 · WorkspaceModel.swift:6-8
对策 右侧固定一个 302 px 检查器，三个互斥 tab（文件 / 变更 / 待办）， ⌘1–3 切换、⌥⌘→ 收起。终端就是画布，历史回到侧栏各自的项目组下。
问题 07

字号设置拍平了系统字阶

.font(.system(size: model.uiFontSize)) 挂在根视图上， 把整棵视图树的字号统一覆盖。.title2 / .caption 这些语义字阶失去相对关系， 界面因此没有层次 —— 这是「看起来平」的直接原因。

YCodeNativeApp.swift:212
对策 改用 .dynamicTypeSize 三档（紧凑 / 标准 / 宽松）， 让系统按比例缩放整个字阶。终端字号独立，不走这条。
02

设计基础

没有 token 体系就没有一致性，这是问题 04 和 07 的根。下面这些值是这份稿子里每一屏的唯一来源。

一条贯穿全稿的决定：整个窗口——包括终端画布——跟随系统外观。 没有「浅色壳 + 深色终端」的混搭。浅色下画布是 #FFFFFF，深色下是 #16181D， 与 chrome 同一套明暗切换。代价是终端的 ANSI 语义色要备两组 （见下方 --t-* token），两组都在各自底色上过 4.5:1。 换来的是：窗口里不存在一块不听系统话的区域 —— 用户在系统里切外观，整个 app 一起变，这是原生应用最基本的承诺。

次要强调

状态语言 —— 只有两个

现在的实现要渲染七种运行态。但对用户来说，看一眼会话只需要回答一个问题：它要不要我？ 所有 agent CLI 都支持 resume，会话永远是可恢复的 —— 所以「已退出」「可恢复」「收到信号」这些都不是用户要判断的东西，点进去就接着跑。 退出码属于排错信息，归诊断，不归列表。

运行中
agent 在干活，不需要你。
running / starting
等你
在等输入、等审批，或刚建好还没选 agent。唯一会进收件箱、会亮侧栏计数的状态。 「在等什么」写在收件箱里，不写在侧栏 —— 侧栏回答「有哪些会话」，收件箱回答「哪些要我、为什么」。
pendingApproval / waitingInput / 未开始

两个状态复用在三处：侧栏会话行、画布窗格头、收件箱条目。 err 与 warn 两个颜色 token 仍然保留 —— 它们用在变更面板的删除行、 「删除会话…」这类破坏性菜单项上，只是不再用来表示会话状态。

1项目与会话合成一列。项目是可折叠的组标题（带活跃会话数），会话是组里的行。 原来的「项目列 + 会话列」两列合并后省出约 220 px，全部给了画布。
2「等你」是侧栏的第一等公民。过滤 chip 上的计数与收件箱同源。 会话行默认只有三样东西：状态点、agent 图标、名称；只有上了画布的行才在右侧追加格位徽标 ⌘⇧N。不挂时长 —— 「跑了 4 分 12 秒」既不影响你做什么，又让每一行都多一列噪音；要看时长去会话信息（⌘I）。
历史会话也在这里 —— 每个项目组的活会话列完之后，跟一行可折叠的「历史会话 · 192」。 历史本来就按 cwd 分组，跟侧栏的组织方式天然一致；点一条是恢复它，这是侧栏的动作，不是检查器的。
3工具栏只放跨会话的动作。布局分段控件、收件箱、⌘K、检查器开关。 加项目 / 删项目 / 上移下移全部移进侧栏右键菜单（见屏 03）。
4画布没有标签页，只有窗格。「单个」布局就是一个窗格占满， 窗格头（28 px）就是这个会话的标识条，只有五样东西：状态点、名称、agent·模型、⌘⇧N、移出画布。 查找（⌘F）、会话信息（⌘I）都有快捷键和右键菜单，不必在这条上各占一个按钮 —— 窗格头每天看几百次，放按钮的成本是永久的。 四宫格时每格一条，完全同一个组件 —— 会话的容器只有一种。
原来的画布工具条（布局菜单 + 5 个面板开关 + 字号加减）随之拆开：布局上了工具栏， 面板成了检查器 tab，字号去了状态栏。
5检查器只有三个 tab，且互斥。文件 / 变更 / 待办 —— 都是「当前工作区的切面」。 ⌘1–3 切换，⌥⌘→ 整体收起，宽度只有一个值。 历史不在这里：它是过去的会话，点一条是恢复它，属于侧栏（见标注 2 下方）。
6新建会话在侧栏底部，不在工具栏。它属于「当前项目」这个上下文， 放在侧栏底部与 Finder / Xcode 的惯例一致，⌘N 仍然可用。
7状态栏是元数据的唯一归宿。分支与变更数、会话计数、worktree 数、PID、终端字号、agent 版本 —— 这些以前铺在主区（问题 01、05）的东西，在这里各占一格，随时可看，从不挡路。

5已完成默认折叠。 做完的事只在需要回看时展开，不占据清单顶部的注意力。

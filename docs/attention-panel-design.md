# Tandock 需关注面板设计

日期：2026-10-18  
状态：按本设计实施；验证分层及剩余边界见[实施记录](attention-panel-validation.md)。设计已纳入三项独立审查的修订意见。

在右侧增加「需关注」面板，汇总需要用户查看或介入的会话。第一版提供关注提醒、明确已读和会话定位；只有掌握完整请求生命周期的适配器，才有资格把提醒升级为准确的待处理请求。

## 目标与范围

用户不必逐个打开终端，即可发现审批相关提示、待查看结果和会话异常，并快速进入对应 CLI。

第一版包括：

- 右侧独立面板、工具栏数量提示，以及「需要关注」「等待查看」两组列表。
- 按会话汇总提醒，保留项目、会话名、原因、摘要和时间。
- 点击定位活跃 CLI；退出会话提供独立的恢复操作。
- 手动标记已读、收起提醒，多窗口共享状态。
- 有限的 hook 分类、运行代次隔离、旧事件过滤，以及进程异常退出提醒。
- 面板、侧栏与系统通知使用一致的分类和措辞。
- 系统通知标题仅显示会话名称，不显示状态后缀或项目副标题，正文保留消息摘要；会话名与界面的命名规则一致。

第一版不包括：面板内批准或回答、逐请求审批队列、仅因选中或前台显示而自动已读、跨应用重启保留、终端文本或标题推测审批、AI 分析终端内容、恢复暂缓的原生会话或统一输入功能。

## 现状与审查结论

| 当前实现 | 对方案的影响 | 修订决定 |
| --- | --- | --- |
| Claude 接入 Stop 和 permission_prompt；Codex 接入完成通知和 PermissionRequest | 缺少完整的请求解决事件，不能持续断言仍在等人 | 展示事件提醒；没有闭环时明确标为待核实 |
| hook 事件没有运行代次、轮次和请求标识 | 旧事件可能污染新运行；不能可靠列出多个未解决请求 | 增加运行代次；第一版按会话汇总 |
| attentionEvents 属于各窗口的 WorkspaceModel | 新窗口无法补齐旧消息，各窗口确认状态可能不同 | 改为应用内共享状态源 |
| 任意终端输出会清除关注 | 重绘可能消除仍需关注的提示 | 取消输出清除；只由明确用户动作或生命周期事件更新 |
| 非 live 终端视图出现时自动恢复会话 | 单纯打开退出会话也可能启动进程 | 退出项不进入自动恢复路径，另设恢复按钮 |
| 只有焦点从未选中变为选中时才交还输入焦点 | 点击当前会话的关注项未必能立即输入 | 新增明确的终端焦点请求 |
| 没有结果位置和有效的视口已读判定 | 选中会话不能证明结果已看见 | 标记已读、点击结果前往会话或在对应运行中继续输入时确认结果 |

## 面板与消息展示

面板沿用现有原生卡片样式，标题为「需关注」，支持关闭和调整位置。关闭仅隐藏面板，不清除消息。

| 分组 | 类型与示例 | 主操作 | 次操作 |
| --- | --- | --- | --- |
| 需要关注 | 橙色：审批提醒 · 待核实 | 前往会话 | 收起提醒 |
| 需要关注 | 橙色：输入提醒 · 待核实，仅适配器实际支持时出现 | 前往会话 | 收起提醒 |
| 需要关注 | 红色：启动失败／意外退出 | 查看原因 | 收起提醒 |
| 等待查看 | 蓝色：本轮已结束 | 查看会话 | 标记已读 |
| 等待查看 | 中性色：会话已结束，原关注状态已失效 | 查看摘要 | 收起提醒 |

每行展示：类型文字、最多两行摘要、项目／会话名称、首次提醒时间。颜色仅辅助识别，不能取代类型文字。

- 需要关注排在等待查看之前；同组按首次提醒时间升序，先处理等待最久的事项。
- 同一运行的重复提醒更新摘要和最近时间，不改变首次提醒时间，不把条目反复移到队首。
- 同一会话可以同时有一条关注汇总和一条最新结果提醒。查看结果只确认该结果；本轮结束事件会移除该运行中此前的审批提醒，较新或明确属于其他轮次的提醒保留。
- 第一版只保留每个会话最新的结果摘要，不承担历史消息归档。
- 操作完成后不自动切换下一个 CLI，不移动终端输入焦点到其他会话。
- 工具栏数字表示需要关注的会话数；没有需要关注而仍有未读结果时显示蓝点。面板内分别显示两组数量。
- 无消息时显示「暂无已接收的关注消息」。未接入或未验证的 CLI 另显示能力说明，不能以空列表表示所有会话均正常。

新消息只更新列表和标记，不自动打开面板、不抢焦点。系统通知沿用现有开关与前后台策略，不因新增面板增加弹窗频率。

### 窄窗口布局

不能把第五张卡片无条件加入现有的两卡一列布局。显示所有已打开面板所需的最小宽度超过可用区域时，右侧降为单列面板切换：保留所有面板的打开状态，以紧凑选择器切换当前卡片；窗口变宽后恢复原顺序和布局。

不自动关闭用户原有面板，不覆盖文件或终端内容；需关注入口在降级布局下仍显示数量提示。

## 状态与信号规则

运行状态、关注提醒、已读状态分别保存。CLI 进程存活只代表会话进程存在，不代表模型正在工作；普通终端输出不证明审批结束、任务成功或用户已查看。

| 信号 | 第一版解释 | 禁止推导 |
| --- | --- | --- |
| Claude permission_prompt | 收到审批提示，进入需要关注，显示待核实 | 此请求此刻仍未解决 |
| Codex PermissionRequest | 发生审批流程相关事件，进入需要关注，显示待核实 | 用户一定看到了审批框；其他 hook 未自动决定 |
| Claude Stop／Codex 已识别的完成通知 | 收到响应结束相关事件，生成结果未读提醒 | 用户任务已经验收；所有审批已解决；后台工作全结束 |
| 明确启动错误／非预期异常退出 | 生成异常提醒 | 正常退出或用户主动停止也属于失败 |
| 未知事件或未知来源 | 忽略状态转换，保留必要诊断 | 默认当作完成事件 |
| 普通输出、重绘、标题变化或长时间静默 | 不改变关注和已读状态 | 自动确认完成、审批成功、无人处理 |

Pi 和自定义 CLI 第一版没有承诺审批、提问和完成检测；仅使用应用掌握的启动及进程退出事实。后续每增加一种适配，应明确其创建、更新、解决、失效信号以及支持的 CLI 版本。

### 生命周期

- 新关注事件：创建或更新该会话当前运行的关注汇总，并生成新的事项版本。
- 本轮结束通知：更新结果提醒为未读，并移除同一会话、同一运行中时间不晚于该事件的审批提醒。双方都有轮次 ID 时还须一致；其他会话、其他运行、较新或其他明确轮次的审批以及异常提醒均不清除。此操作仅收起已过时的本地提醒，不宣称请求已批准。
- 用户收起：仅确认该版本的本地提醒；不向 CLI 发送批准、拒绝或任何输入。
- 用户标记已读：仅确认操作时看到的结果版本。操作期间到达的新结果保持未读。
- 用户点击结果的前往会话：定位并交还键盘焦点，同时确认该结果版本；即使只有一个会话也执行。用户在终端继续输入时，立即确认该运行已有的最新结果，不等待下一轮回复完成。普通输出、终端协议响应、单纯选中或前台显示均不触发已读；审批提醒保持独立。
- 关闭会话、主动停止或正常退出：清除该会话的关注提醒和未读结果，并同步所有窗口。异常退出保留结果摘要并提供准确的失败原因。
- 重新启动：新运行获得新代次，旧代次不能再创建当前待处理项。此前未读结果可保留，但明确属于上次运行。
- 归档或删除：移除相应会话的面板事项，拒绝其迟到事件。取消归档不重放旧审批提醒。
- 应用重启：第一版从空的关注状态开始，不恢复未经核实的待审批项，也不重放系统通知。

审批提醒保留到用户收起、收到适用的本轮结束事件或运行失效。单纯键盘输入和普通输出不证明审批已经解决，也不用超时推断审批结果。缺少轮次 ID 时依照运行身份和事件接收时间收起此前提醒，不宣称逐请求解决状态。

## 数据归属与事件身份

应用内共享关注服务按规范化 dataRoot 隔离，统一接收、校验、归并和确认事项。各窗口读取同一份状态并过滤展示，不再各自消费 hook 后维护独立字典。新开窗口立即取得当前快照。

第一版需要保留以下信息：

| 信息 | 用途 |
| --- | --- |
| 数据根、项目 ID、会话 ID | 隔离状态并定位会话 |
| 运行代次 | 区分同一会话的不同进程运行，拒绝旧事件 |
| 来源、原始事件类型、提醒分类 | 保留事件语义，统一文案 |
| 事项 ID、递增版本 | 避免旧的已读或收起操作覆盖新提醒 |
| 首次时间、最近时间、摘要 | 稳定排序与展示 |
| 已读／收起版本、有效性 | 区分用户确认和运行失效 |
| 原生会话 ID、轮次 ID、请求 ID，如来源提供 | 额外校验与未来请求关联，缺失时不伪造 |

每次受管进程启动生成新的运行代次，经启动环境和 tandock-notify 传回。接收前核对当前运行、来源、会话存在性与归档状态；有明确原生身份冲突的事件不得写入当前事项。新代次字段是第一版内部协议变更，不增加用户配置项。

升级后仍在运行、无法携带代次的旧进程不能被当作已完整接入；标明需恢复会话后生效，不为取得信号自动重启用户任务。

有稳定事件 ID 时按 ID 去重。没有 ID 时保留短时间指纹去重，并按会话汇总；这是尽力去重，不能保证识别每次相同文本的真实请求。运行代次必须纳入指纹，不能让前一运行抑制后一运行的事件。

系统通知只消费共享服务接受并分类后的事件，不能继续独立把原始 permission_request 显示为确定的「需要批准」。未知会话、旧运行、归档会话的事件不得产生通知。

## 点击与窗口行为

主窗口默认汇总当前数据根的全部项目；项目专属窗口仅展示其固定项目。固定范围由窗口创建时传入，不能使用随画布焦点变化的 selectedProjectID。

需关注面板是现有右侧项目上下文规则的明确例外：其范围保持稳定；文件、变更、待办和项目终端继续跟随焦点项目。

| 目标情况 | 点击行为 |
| --- | --- |
| 活跃会话已在画布中 | 聚焦该窗格，并显式交还键盘输入焦点 |
| 活跃会话位于其他标签 | 切到对应标签并聚焦 CLI |
| 活跃会话未显示 | 按现有侧栏打开策略加入画布；分屏满四格时替换焦点位置，原进程和标签保留 |
| 目标就是当前会话 | 仍执行一次明确焦点请求，不能只更新 selectedSessionID |
| 会话已退出或启动失败 | 在关注面板查看摘要／原因，只有点击恢复或重试才启动进程 |
| 会话已删除或归档 | 移除失效事项，不创建替代会话 |

第一版始终在当前窗口完成定位，不自动跳往另一个项目窗口。点击不发送 Enter，不替用户选项，不自动改变终端滚动位置。点击结果项会确认该结果版本；审批及异常提醒不随定位清除。

结束通知顶部显示会话标题，保留蓝色未读图标，不再显示「本轮已结束」；下方依次显示消息摘要、项目名和时间，不重复会话标题。所有结束通知均以整张卡片作为点击入口，确认对应结果版本，不再另设「前往会话」「标记已读」按钮。会话仍在运行时同时定位并聚焦会话；已退出时只标记已读，不启动进程。恢复会话从会话列表操作。审批、异常提醒的详情、恢复与独立收起操作保留。

CLI 进程退出时（正常退出、非零退出或信号终止）自动收起所有窗口内对应的窗格，会话记录保留。正常退出清除该会话的通知；异常退出保留结果未读和失败提醒。主动关闭窗格或停止会话也清除其通知，迟到的旧运行事件不能重新生成通知。主动重启过程中的旧进程退出不收起窗格，仍保留未读结果；旧运行或其他数据根的退出事件不能影响当前画布。

点击与进程状态变化存在竞争时，以执行动作前重新检查的状态为准。定位入口必须避免触发非 live 视图的 onAppear 自动恢复；不能仅在点击前检查一次。

## 实施落点

预计涉及超过 8 个文件，跨 Core、helper、App 和测试，但不新增后台服务或外部账号。必须把事件身份、共享状态和 UI 作为同一可验收功能交付，不能只上线列表而保留旧清除逻辑。

| 模块 | 改动 |
| --- | --- |
| AgentHookNotifications 与新关注模型 | 白名单分类、运行代次、事项版本、归并及生命周期规则 |
| Agent 启动环境与 TandockNotify | 注入和回传运行代次，保留原 hook 所有权与链式调用行为 |
| 应用内共享关注服务 | 按数据根保存内存状态，输出快照和变化；窗口关闭不丢状态 |
| WorkspaceModel | 订阅共享状态、固定范围过滤、取消输出清除、提供安全定位 |
| 新 AttentionPanelView | 两组列表、摘要、手动已读、收起及恢复入口 |
| TerminalWorkspaceView | 显式焦点请求、退出会话的安全入口、窄窗布局降级 |
| 面板枚举、工具栏、菜单和本地化 | 增加需关注入口，保留原有快捷键分配，双语同步 |
| SystemNotificationCoordinator 与侧栏状态 | 消费同一分类，提示不确定性，区分关注与未读 |
| 测试和功能文档 | 更新原“输出清除关注”测试，同步产品范围及验收清单 |

第一版无数据库迁移、无跨重启持久化、无新增密钥或配置开关；回退功能代码不需要迁移用户数据。helper 增加的事件字段不应改变 CLI 的审批决定或失败行为。

## 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 完成／审批通知 | 正确分组，审批相关事件显示待核实，不把事件当作任务验收 |
| 未知事件 | 不被默认识别为完成，不产生错误未读或系统通知 |
| 输出与重绘 | 关注不消失；大量输出不导致整窗持续刷新 |
| 同文重复事件 | 短期重试不刷屏；不同运行互不去重；汇总不声称完整请求列表 |
| 旧事件迟到 | 退出、恢复、归档和删除后的旧事件不能复活当前待处理项 |
| 确认与新事件并发 | 对旧版本标记已读或收起，不清除刚到的新版本 |
| 多窗口 | 已有窗口与新开窗口立即一致；确认同步；不同数据根互不影响 |
| 项目范围 | 主窗口跨项目；项目窗口固定范围；定位后列表不突然换项目 |
| 定位与焦点 | 当前窗格、隐藏标签、未显示会话均准确定位；点击后可直接键入 |
| 退出与启动失败 | 点击只看提醒；恢复／重试独立触发；定位中退出也不自动重启 |
| 面板布局 | 五面板同时打开、最小窗口及拖拽宽度下无裁切；降级后可访问全部面板 |
| 已读 | 选中或前台显示不会自行已读；点击结果前往会话确认对应版本，继续输入确认对应运行已有结果；输出及协议响应不清除，后续新结果仍未读 |
| 通知 | 关闭、仅后台、始终策略不变；同一接受事件不因窗口数量重复通知 |
| 实际 CLI | 对宣称支持的 CLI 分别真实触发完成及审批相关事件，记录版本与接入条件 |

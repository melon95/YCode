# M5.4 正式数据切换及回退演练

状态：阻塞（M5.3 尚无可公证的正式发布包）

## 交付物

- `scripts/cutover.sh prepare`：要求旧版与原生版均停止，完整复制旧数据，并用 SQLite online backup 捕获 WAL 中的最新记录。
- `activate`：只从一致性快照执行 `ycode-migrate`，保留旧 app 与旧数据后再安装正式标识原生包；任一步失败都恢复旧数据与旧 app。
- `rollback`：先保留切换后新增的原生数据，再恢复旧数据与旧 app，不静默丢弃新增数据。
- `status`：读取快照 manifest，明确 prepared / active / rolled_back 状态。
- 正式 `activate` 必须同时提供 app 与 ZIP，并先以 notarized 口径通过 Developer ID、Hardened Runtime、安全时间戳、公证票据、Gatekeeper 和 app/ZIP 一致性校验；ad-hoc 候选包不能进入正式切换。
- 隔离演练必须显式传入 `--rehearsal`，应用、数据和快照路径全部限制在 `/tmp` 或 `/private/tmp`，且 manifest 会绑定演练模式与精确目标路径，避免误操作正式目录或串用另一份快照。

演练根目录：`/private/tmp/ycode-cutover-rehearsal.wYnXPq`。

顺序：prepare → activate → 检查迁移数据与应用 → rollback → 再次检查。

## 本轮数据安全记录

最终候选包检查时曾误用无效变量 `YCODE_DATA_ROOT` 启动，导致正式旧数据目录被短暂打开；发现界面出现旧项目后立即终止。只读复核确认 `config.json` 修改时间仍为 2026-09-09，数据库 `PRAGMA integrity_check=ok`，但 `ycode.db` / WAL 修改时间更新到 2026-09-18 15:23，且存在原生元数据表 `native_project_order`、`native_workspace_state`。没有在缺乏前态快照时擅自回滚。

随后改用正确变量 `YCODE_NATIVE_DATA_ROOT=/private/tmp/ycode-release-final.uHsIdW` 重验；可见界面为“还没有项目”，证明隔离数据目录生效。

为避免同类误用再次静默回落，`YCodeDataRootResolver` 现将 `YCODE_DATA_ROOT` 作为安全兼容别名；优先级仍为 `--data-root` → `YCODE_NATIVE_DATA_ROOT` → 兼容别名 → 默认正式目录。定向测试覆盖正确变量优先、别名隔离和默认回退并通过。正式文档及脚本继续只使用 `YCODE_NATIVE_DATA_ROOT`。

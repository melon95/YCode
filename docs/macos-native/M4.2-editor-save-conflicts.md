# M4.2 多标签编辑器与保存冲突处理

日期：2026-09-17
状态：通过

## 实现结果

- 文件工作区加入项目级多标签模型：单击文件先进入预览标签，打开下一个文件会替换未固定预览；双击、编辑或明确打开会固定标签。
- 每个标签独立保留内存草稿、磁盘基线和脏状态；切换文件、返回文件树或切换项目不会把另一项目的同名路径混入当前编辑器。
- 编辑区使用系统 `NSTextView(usingTextLayoutManager: true)` / TextKit 2，通过窄 `NSViewRepresentable` 接入 SwiftUI；保留原生焦点、选择、中文输入和撤销栈。
- `⌘S`、工具栏保存与当前标签一致；UTF-8 文本通过同目录临时文件原子替换，保留原文件 POSIX 权限。
- 保存前精确比较磁盘内容与打开时基线。发现外部修改时，普通保存只弹出“重新加载 / 明确覆盖 / 取消”，不会静默覆盖。
- 脏标签关闭前显示丢弃确认；文件树删除和项目移除会阻止包含未保存标签的路径，避免旁路丢失草稿。
- 每秒检查已打开文本文件：干净标签自动接收外部更新，脏标签保留草稿并显示冲突横幅；重新加载始终重新读取当前磁盘内容，不使用过期缓存。
- 二进制、无效 UTF-8、绝对路径、路径穿越和符号链接逃逸不会进入文本保存链路。

## 可见界面与磁盘验收

使用隔离数据目录 `/tmp/ycode-m42-acceptance.sFVJaG/data` 和临时项目 `编辑 项目`：

1. 打开 `A 文件.txt` 后显示预览标签；编辑为中文草稿后自动固定并标记“未保存”。
2. 再打开 `B 文件.txt`，切回 A 后草稿逐字保留；双击 B 后预览提示消失，标签转为固定。
3. 在 B 中替换文本后执行 `⌘Z`，内容和“已保存”状态都恢复；再次编辑并执行 `⌘S`，磁盘精确读回 `已保存 B\n`。
4. A 保持脏草稿时从应用外把磁盘内容改为 `外部版本 A\n`；界面显示冲突横幅，草稿仍为 `本地草稿 A\n第二行\n`。
5. 此时执行 `⌘S` 只出现重新加载、明确覆盖和取消选择；选择取消后草稿与外部磁盘版本均未改变。
6. 点击 A 的关闭按钮会显示丢弃提示；选择取消后标签和草稿仍在。
7. B 处于干净状态时从应用外更新为 `外部更新 B\n`，标签自动刷新且保持“已保存”。

界面的“重新加载”和“覆盖”属于会丢弃一侧内容的明确动作，本次可见验收检查了入口、警告文案和取消分支；真正的重新加载/覆盖结果由隔离临时目录中的文件服务测试执行，没有对用户项目执行破坏性操作。

## 技术边界

- `STTextView` 能力合适，但 GPLv3 / 商业双许可不适合直接并入当前 MIT 项目。
- `CodeEditSourceEditor` 使用 MIT 许可，但其项目仍明确处于开发阶段；首版继续采用系统 TextKit 2，M4.3 在其上增加语法高亮与原生预览。
- 本阶段实现的是标签关闭提示；应用窗口级未保存恢复不在旧版 M4.2 对等范围内，未宣称已覆盖。

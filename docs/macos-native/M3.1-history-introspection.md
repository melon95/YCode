# M3.1 Claude/Codex 历史扫描、解析、展示与搜索

日期：2026-09-16

状态：通过

## 实现结果

- 原生核心层直接只读扫描 Claude 与 Codex 的 JSONL 历史，不复制、不改写源文件。
- 统一输出会话、角色、时间、正文、思考、工具调用及其他事件；坏行单独跳过，不中断整批加载。
- 文件追加时只解析新增字节；截断、替换或同大小改写时重新解析，避免重复事件。
- SwiftUI 历史面板支持会话选择、事件展示、正文搜索、结果定位、手动刷新和增量轮询。
- 搜索期间暂停轮询，点击结果后清空查询并定位到对应会话和事件，避免结果列表刷新导致点击失效。

## 性能结果

M0.2 对旧固定样本写定的预算为：扫描不超过 17 ms、解析不超过 159 ms、全量搜索不超过 187 ms。最终对账快照已从当时的 258.9 MiB 增长到 321.7 MiB；以下结果仍直接采用原预算，没有按数据增长放宽门槛。

最终在同一只读静态快照上各跑 7 轮：

| 项目 | 原生 Swift 中位数 | 旧 Rust 中位数 | M0.2 预算 | 结论 |
|---|---:|---:|---:|---|
| 冷扫描 | 15.5 ms | 25 ms | 17 ms | 通过 |
| 冷解析 | 142.5 ms | 242 ms | 159 ms | 通过 |
| 冷全量搜索 | 168.7 ms | 287 ms | 187 ms | 通过 |
| 已建索引搜索 | 11.7 ms | 不适用 | 不适用 | 交互路径记录 |

优化前原生实现的冷扫描和冷解析中位数分别约为 228 ms、455 ms。本轮通过共享只读字节缓冲、避免容器和大字符串重复扫描、并行解析会话文件、为未知事件跳过无用时间解析、只读取 Codex 元数据前缀、映射标题文件以及分块搜索，将扫描、解析和冷搜索全部压到原预算内。ASCII 查询使用无分配大小写匹配；非 ASCII 查询保留 Unicode 大小写搜索路径。

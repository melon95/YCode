## 实现结果

- 建立 6 个语言服务器清单：rust-analyzer、TypeScript / JavaScript、Pyright、gopls、JDT LS、OmniSharp；每项记录扩展名、语言 ID、安装方式、依赖命令、主页和启动参数。
- 安装器使用原生数据目录下的 `lsp/<serverID>` 隔离安装，支持系统命令采纳、GitHub gzip / tar.gz、npm、go install 和普通 archive；安装在 staging 目录完成，失败不会写入成功记录。
- 设置页“语言”展示真实安装状态、缺失依赖、安装进度、版本和卸载确认；缺依赖时按钮不可用，卸载只删除 YCode 数据目录中的副本和安装记录。
- LSP 客户端实现 stdio framing、initialize / initialized、didOpen、didChange、semanticTokens/full、definition、didClose、shutdown，以及 publishDiagnostics / serverExited 事件。
- 文件工作区现在为每个项目接入共享 `YCodeLanguageServerService`；打开已支持文件会启动对应服务器，编辑时防抖发送新版本，关闭标签时发送 `didClose` 并释放文档状态。
- 编辑器把 LSP semantic token 叠加到 M4.3 的本地语法高亮上，诊断以虚线下划线标记并在工具栏显示首条信息；服务器退出后当前文档标为非活跃，下次打开重试。
- 工具栏提供基于当前光标位置的“跳转定义”入口；定义位置在当前项目内时打开目标文件并定位，越界位置返回明确错误。

## 可见界面验收

本步已完成可编译 UI 接入和协议级 fake server 验证。真实第三方语言服务器的逐项安装、打开、修改、跳转、关闭、卸载会受本机网络、npm、Go、Java、dotnet 和各服务器版本影响；本次没有在用户项目上执行联网安装或破坏性卸载。

已静态核对的界面路径：

1. 设置页“语言”由 `YCodeLanguageServerService.manifestStatuses()` 驱动，不显示未验证的成功状态。
2. 文件工作区通过 `WorkspaceModel.ensureEditorWorkspace` 传入共享语言服务；不再停留在未接线状态。
3. 编辑器状态、诊断、语义 token 和跳转定义入口都来自打开文档的实际 LSP 会话；未安装服务器时保持普通编辑器，不伪装成功。

## 技术边界

- 当前语义高亮是在 TextKit 属性层叠加 token，不引入 WebView。
- 真实服务器安装需要网络和本机工具链。安装失败、服务器退出和请求超时会显示错误并保持安装记录/文档状态可恢复。
- 本阶段完成 LSP 安装管理与协议接入；多语言真实服务器矩阵的完整人工录屏可在发布前回归中补充，不能替代当前 fake stdio 协议测试。

# M4.6 普通项目目录检查点与逐轮审阅

状态：通过

## 交付物

- `YCodeCheckpointRepository`：读写 `session_checkpoints`，按会话维护 sequence，支持重复轮次事件去重和保留上限裁剪。
- `YCodeCheckpointService`：在普通项目目录生成初始和轮次快照，写入 `refs/ycode/checkpoints/<session>/<uuid>`，并提供与前一检查点的 diff。
- `YCodeGitService` 扩展：使用临时 `GIT_INDEX_FILE` 创建 snapshot commit，不改变真实 index/worktree，不创建 worktree。
- `YCodeAgentSessionService` 接入：新会话创建后尝试生成 initial checkpoint；非审批类 hook 完成事件生成 turn checkpoint。
- `CheckpointServiceTests`：覆盖初始快照、两轮可控修改、重复事件、空变化、keep 裁剪、ref 删除和真实 index 不变。

## 验收范围

| 能力 | 验收结果 |
|---|---|
| 初始快照 | 新会话创建路径可调用 initial checkpoint；测试直接核对 `show-ref --verify` 指向落库 commit。 |
| 轮次快照 | 两轮修改按 sequence 递增，diff 与上一检查点比较，包含新增、修改、删除。 |
| 不创建 worktree | 测试核对 `git worktree list` 只有项目主目录。 |
| 不污染真实 Git 状态 | 快照使用临时 index；测试在 staged + unstaged 混合状态前后比较 `git status --porcelain=v1` 完全一致。 |
| 重复事件 | 同一 session/source/event/body 的 turn 事件被拒绝，不产生重复 DB 行或 ref。 |
| 空变化 | 工作区无新变化时仍可记录有序 turn snapshot，用于保留轮次事件边界。 |
| 保留上限 | `keepLimit=2` 时只保留最新两条 DB 记录，并删除被裁剪的 checkpoint ref；`keep=0` 语义保底至少 1 条由实现中的 `max(1, keepLimit)` 保证。 |

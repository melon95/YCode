# M0.4 原生编辑器 / 预览验证与架构决策

状态：**通过**

环境：macOS 26.6.2 arm64；Swift 6.3 / Xcode 26.4；部署下限 macOS 14.0

## 决策

| 能力 | 采用方案 | 版本 / 构建约束 | 结论 |
|---|---|---|---|
| 编辑器 | 系统 `NSTextView(usingTextLayoutManager: true)` / TextKit 2 | 随 macOS；最低 14.0 | 中文输入、撤销、长文件与系统文本行为均可用；不引入编辑器许可证约束 |
| Markdown | `swift-markdown` → 自有 AppKit attributed-string renderer | 固定 0.8.0；`swift-cmark` 0.8.0 | 保留标题、段落、列表和 inline 样式，不用 WebView |
| 图片 / SVG | `NSImage` + `NSImageView` | 随 macOS | 位图与 SVG 原生解码；损坏内容显式失败 |
| 语法高亮 | TextKit 2 属性着色 + 自有离线词法/结构 token 扫描器 | 不增加语法运行时依赖；M4.4 的 LSP 语义 token 在其上增强 | 39 组均有原生高亮；未知类型回落可编辑纯文本 |
| 构建 | SwiftPM 验证包；正式工程采用 SwiftPM 模块 + Xcode app target | 开发 arm64；发布 Universal 2（arm64 + x86_64） | 验证包可独立运行；M1 并入正式工程 |

未采用：

- `STTextView`：技术能力合适，但当前是 GPLv3 / 商业双许可，不直接放进 MIT 项目。
- `CodeEditSourceEditor`：MIT，但项目 README 明示仍在开发、未达到生产可用；不作为首版核心底座。
- Foundation 单独的 `AttributedString(markdown:)`：inline 可用，但可见验证发现会压平块级布局，已换为 `swift-markdown` 语法树。

语法清单以 `SyntaxLanguageRegistry.swift` 为唯一原生输入，共 **39 组**。原 M0.1 写成“14 + 23 = 37”是计数错误；实际第一表 16 组、第二表 23 组，已纠正并加自动断言。

## M4.3 集成修订

M0.4 的验证程序曾把 Tree-sitter 记作预选方案。正式接入时复核发现：低层 Swift 封装仍需逐个维护语法 C target，而现成语言合集要么不能覆盖既定 39 组，要么首次使用时下载语法，无法满足离线、可复现构建和完整覆盖这三个条件。因此 M4.3 改用无网络依赖的原生 token 扫描器，并为 39 组全部建立样本断言；这不是 Tree-sitter AST 级高亮，LSP 语义精度由 M4.4 继续增强。该修订不降低 M4.3 的功能验收：已支持的文件不再静默回落纯文本，未知扩展名仍保持可编辑。

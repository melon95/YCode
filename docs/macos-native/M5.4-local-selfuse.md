### 2. `cutover.sh` 新增 `--local` 口径

原脚本只有两档：`--rehearsal`（路径锁定 `/tmp`）和正式（强制 `--native-archive` + notarized 口径）。本地自用落在中间，此前没有可走的口径。

- 新增 `--local`，`MODE` 由二值 `REHEARSAL` 改为三值 `rehearsal` / `local` / `formal`；`REHEARSAL` 仅为兼容旧 manifest 保留。
- manifest 新增 `mode=` 字段，`require_manifest_context` 优先比对 `mode`，缺失时回落到旧 `rehearsal` 字段。三种口径的快照**严格互斥**，不能串用。
- `local` 口径的候选包校验走 `verify_release_candidate.sh` 的 **prepare 级**：深度签名、universal2（主程序 + 4 helper + Sparkle）、bundle id / 版本 / 最低系统 / `ycode://`、app 与 ZIP 逐字节一致、prepare 包不得带更新 feed 或公钥。**除 Developer ID 与公证外没有任何放宽。**

### 3. 新增 `adopt` 动作（仅 `--local`）

现有 `activate` 假设数据仍是旧版的、需要跑 `ycode-migrate`。但当前数据**已被原生版接管并持续写入**，再跑一次 migrate 既无必要也有风险。

`adopt` 的语义是"数据已在使用，补齐保护"：

1. 要求应用已退出、快照位置安全、快照目录不存在；
2. 以 prepare 口径校验候选包；
3. `ditto` 全量数据 + SQLite online backup 到快照，校验 `integrity_check=ok`；
4. 归档 `/Applications` 的旧版 app 到快照（实现单向规则：旧 app 不再留在 `/Applications`）；
5. 先把候选包 stage 到快照再 `mv` 到位，失败则恢复旧 app；
6. 写 manifest `state=adopted` / `mode=local`。

`adopt` **不移动、不重建 DATA_ROOT**——数据原地继续使用。

`rollback` 相应支持 `adopted` 状态：把当前数据移到 `native-before-rollback` 保留，再从 `legacy-data` 快照恢复，并还原旧 app。切换后新增数据不会被静默丢弃。

## 未解决项

1. **`/usr/local/bin/ycode` 是断链**。该符号链接仍指向旧版 Tauri 的路径结构 `Contents/Resources/binaries/ycode-cli`，而原生版 helper 位于 `Contents/Resources/ycode`，因此 `ycode` 命令当前不可用。
   `CLIIntegration.swift:590` 的 `owns()` 同时认可新旧两种路径后缀，会把该链接判定为 YCode 自己的并覆盖重建，不会拒绝。修复需在应用内"设置 → 集成 → 安装命令行工具"执行一次——安装器通过 `osascript … with administrator privileges` 提权（`CLIIntegration.swift:593`），需要用户在系统授权框中确认，无法由脚本代劳。修复后应重新核对链接目标与 `ycode .` 的实际行为（IN.7–IN.9）。
2. 本地自用期从 2026-09-20 起算，应记录每日问题清单；自用满 4 周且零回退方可解除 M5.5 的冻结。

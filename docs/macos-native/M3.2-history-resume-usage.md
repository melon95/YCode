# M3.2 历史恢复与用量统计

日期：2026-09-16

状态：通过

## 实现结果

- 历史面板可用 Claude/Codex 原始会话 ID 恢复到原生终端；同一项目中已运行的同一会话只聚焦，不重复启动。
- 恢复继续使用配置中的 `introspect` 映射；缺少对应 Agent 时显示明确错误，不猜测命令。
- 原生 Core 只读统计已有 JSONL：Claude 按 `message.id` 去重并取最大累计副本，无 ID 消息分别计数；Codex 只取最后一条累计 `token_count`，并从输入中拆出缓存读取。
- 用量按会话、项目、模型、UTC 日期聚合；未知模型保留 Token、费用为零；`reasoning` 单独展示且不重复加入总 Token。
- 设置页“用量”已改为原生只读报表，包含总览、Token 分类、项目、最近日期、模型和会话维度，并明确费用只是离线估算。

## 固定快照对账

沿用 M3.1 的 321.7 MiB 一次性只读快照，同时运行旧 Rust 与原生 Swift 探针。两侧结果一致：

| 维度 | 旧 Rust | 原生 Swift |
|---|---:|---:|
| 有用量会话 | 33 | 33 |
| 输入 Token | 6,615,238 | 6,615,238 |
| 输出 Token | 3,485,239 | 3,485,239 |
| 缓存写入 Token | 238,827,315 | 238,827,315 |
| 缓存读取 Token | 1,337,613,540 | 1,337,613,540 |
| 推理 Token | 165,413 | 165,413 |
| 总 Token | 1,586,541,332 | 1,586,541,332 |
| 费用（美分） | 602,111 | 602,111 |
| 模型集合 | 7 个，一致 | 7 个，一致 |
| UTC 日期集合 | 22 天，一致 | 22 天，一致 |

原生 Release 探针对该快照的单次统计耗时约 2.38 秒；设置页在后台统计并显示加载态，不阻塞主线程。

## 边界验证

- Claude 相同消息 ID 的重复事件只计一次，保留 Token 最大副本。
- Claude 缺失消息 ID 的两条记录分别计数。
- Codex 多条累计事件只取最后一条，并验证缓存输入拆分和推理 Token 不重复计总量。
- 缺失模型仍计 Token、费用为零。
- `23:59:59.900Z` 与次日 `00:00:00Z` 分入不同 UTC 日期。
- 同一项目重复提供相同工作目录时，会话文件只统计一次。

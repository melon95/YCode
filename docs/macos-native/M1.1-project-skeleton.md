# M1.1 原生工程骨架验收

状态：**通过**

环境：macOS 26.6.2 arm64；Swift 6.3 / Xcode 26.4；部署下限 macOS 14.0

## 交付

- 正式 SwiftPM 工程：`macos/Package.swift`
- 应用目标：`YCodeApp`（SwiftUI 三栏窗口）
- 核心库：`YCodeCore`
- 辅助程序目标：`ycode`、`ycode-mcp`、`ycode-notify`
- 构建入口：`macos/scripts/build_and_run.sh`
- 应用：`macos/dist/YCode Native Dev.app`
- 完整干净构建日志：`macos/dist/build.log`

应用标识为 `dev.ycode.native.dev`，开发数据位置为 `~/Library/Application Support/dev.ycode.native.dev`；它与旧数据目录 `~/Library/Application Support/dev.ycode.ycode` 不同。M1.2 接入旧数据时只操作副本。

当前三个辅助程序只支持 `--version`，其他调用明确返回“对应步骤尚未启用”，不伪装成已迁移功能，也未安装到用户 PATH。

## 验证结果

| 验收项 | 实际结果 |
|---|---|
| 干净构建 | `swift package clean` 后应用 13.34 s 构建成功；三个 helper 分别 1.03 / 0.88 / 0.78 s |
| 测试 | 3 项通过：开发数据隔离、目标名称、Universal 2 发布架构契约 |
| 打包 / 签名 | ad-hoc 签名通过 `codesign --verify --deep --strict` |
| 可见启动 | 干净重建后的 `YCodeApp` pid 90011；原生三栏窗口可见，进程存活 |
| 菜单 | “迁移 → 显示构建信息”可操作；显示版本、开发 bundle id、发布架构 |
| 依赖边界 | SwiftPM 报告 `No external dependencies found`；Mach-O 只链接系统 / Swift 运行库，不链接旧 React、Tauri 或 Rust 应用 |
| Helper | 三个 bundle 内 helper 的 `--version` 均返回 `0.1.0-native-dev` |

开发构建产物为本机 arm64；正式发布约束已固定为 Universal 2（arm64 + x86_64），实际双架构归档在 M5.3 验证，不能用当前单架构开发包冒充发布包。

## 结论

M1.1 通过。下一步 M1.2：只对旧数据库和配置的副本建立 SQLite/JSON 兼容、WAL 一致性备份、导入与失败回退。

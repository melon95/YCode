# M4.1 文件树与文件操作

日期：2026-09-17
状态：通过

## 实现结果

- 新增 Swift 文件服务，递归列出项目目录中的隐藏文件、中文、空格和嵌套路径；保留旧版行为，跳过 `.git`、`node_modules`、`target`，不跟随目录符号链接。
- 新建、重命名和删除只接受项目相对路径；拒绝绝对路径、`..`、重复目标和经符号链接逃逸项目根目录的操作。
- 文件面板使用 SwiftUI 原生树状界面，支持展开、选择、新建文件/文件夹、重命名、删除确认、手动刷新及每秒自动刷新。
- 右键文件时，新建目标为同级目录；右键文件夹或选中文件夹时，新建目标为该文件夹内部。
- 终端文件链接、CLI 文件目标和文件树选择共用项目级文件状态；切换项目保存并恢复各自路径，不会用相同相对路径误绑到另一项目。
- Finder 定位使用 `NSWorkspace.activateFileViewerSelecting`；外部编辑器按 `$VISUAL`、`$EDITOR`、Visual Studio Code、系统默认应用顺序打开。
- 文件面板初始宽度使用 M1.4 导入的旧版宽度，范围保持 180–600 px。
- 修正工作区快捷键枚举，恢复冻结映射：⌘1 终端、⌘2 文件、⌘3 变更、⌘4 待办；历史面板仍由历史命令进入。

## 可见界面与磁盘验收

使用隔离数据目录 `/tmp/ycode-m41-acceptance.SedmPM/data` 和两个临时项目 `项目 一`、`项目 二`：

1. 文件树显示 `.env`、`中文 目录/嵌套/space file.swift`、空格文件名和两个项目各自的 `same.txt`；深层目录可逐级展开。
2. 从界面在根目录创建 `新建 文件.txt` 和 `新建 目录`，再从文件夹右键菜单创建 `新建 目录/子文件.swift`；界面与磁盘结果一致。
3. 输入 `取消文件.txt` 后取消创建，磁盘没有该文件；重命名和删除确认界面取消后同样没有磁盘变化。
4. 再次创建 `新建 文件.txt` 时，面板持续显示“目标已经存在”，原文件未被覆盖。
5. 在应用外创建 `外部 刷新.md` 后，文件树自动出现该文件，不需切换项目或重开面板。
6. 从 `项目 二` 选中 `另一个/嵌套/only-second.md`，切换到 `项目 一` 后只显示项目一的路径；切回项目二时恢复并展开项目二路径。
7. “在访达中显示”打开 `项目 一` 并精确选中 `新建 文件.txt`；“在外部编辑器中打开”在 Visual Studio Code 中打开同一绝对路径。

实际重命名、删除和安全失败分支由隔离临时目录中的文件服务测试执行；可见界面另行验证了入口、初始名称、确认文案及取消不落盘。没有对用户项目执行删除或重命名。

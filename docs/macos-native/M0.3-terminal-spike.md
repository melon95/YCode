## 1. 输入与通过条件

候选底座为 SwiftTerm，验证程序位于 `macos/Spikes`，只验证原生终端底座，不复用 Tauri、React 或 Rust 后端。

固定输入：

- Claude Code 2.1.272、Codex 0.154.0；
- ANSI 红/绿、中文、Emoji、OSC 标题、URL、全屏 TUI；
- 20,000 行 `YBENCH` 中文混排输出；
- 4 个带独立标记的并发 shell；
- 20 次终端视图销毁/重建；
- 600 秒逐秒输出稳定性样本。

通过条件沿用计划与 M0.2 P3：真实 CLI 可交互和中断，视觉样本正确；视图重建不重启进程，隐藏期输出可恢复；连续输出 10 分钟无崩溃、串扰或 PID 变化；20,000 行 shell 侧耗时不超过 0.15 秒。

## 2. 组件结论

锁定候选版本：

- SwiftTerm **1.20.0**，revision `5d14406844143538cd8f8851d2d8a67c1fe443e5`；
- MIT License；
- 最低系统继续保持 macOS 14，当前没有发现要求提高版本的终端能力。

SwiftTerm 可作为 YCode 原生终端渲染底座，但不能直接把 `LocalProcessTerminalView` 当作会话。M2 必须保留本验证形成的边界：

1. `TerminalSession` 长期拥有 `LocalProcess`、无头 `Terminal` 与 256 KiB 原始字节 backlog；
2. 窗口只拥有 `TerminalView`，视图可销毁，重新挂载时先回放 backlog，再接实时字节；
3. PTY 回调统一串行送入终端状态机和界面，不能在读队列与主线程并发访问同一个 `Terminal`；
4. SwiftUI 正式界面只用窄 `NSViewRepresentable` 包装 `TerminalView`，会话和进程池仍由应用级服务拥有；
5. 不使用 SwiftTerm 1.20.0 的 `terminate()` 实现停止语义：它只发 `SIGTERM` 且提前取消进程监视，交互 shell 会忽略信号并可能留下僵尸。YCode 会话层先发 `SIGHUP` 并保持 `waitpid` 监视，超时升级信号；
6. SwiftTerm 回传的是 `waitpid` 原始 status，YCode 边界必须解码后再发布退出码。

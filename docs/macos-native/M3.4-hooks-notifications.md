# M3.4 Agent hook、通知与关注收件箱

日期：2026-09-17
状态：通过

## 实现结果

- Swift `ycode-notify` 读取 Claude/Codex hook 输入，通过每进程 Unix socket 把完成与审批事件送回原生应用；调用失败保持零退出码，不阻塞 Agent。
- Claude 支持 `Stop` 与 `Notification(permission_prompt)`；Codex 支持 `notify` 的 `turn_complete` 与 `PermissionRequest`。解析结果最多保留 200 个字符。
- Agent 会话注入 `YCODE_NOTIFY_SOCK` 与 `YCODE_TERMINAL_ID`；监听器按原生会话 ID 路由，忽略未知会话，2 秒内相同事件去重。
- 监听器为进程级单例，多窗口共享同一 socket；窗口观察者各收到一次事件，不会为每个窗口重复启动监听器或重复发系统通知。
- 关注收件箱区分“已完成一轮”和“需要处理”，显示项目、会话、摘要与时间；点击定位原会话并清除未读。终端继续输出时也会清除该会话关注状态。
- 通知设置支持“始终 / 仅在后台 / 关闭”、测试通知和系统权限状态；系统通知只提示，不代替用户批准 Agent 操作。
- 设置 → 集成可查看、安装和卸载 Claude/Codex hook。Claude 追加带所有权标记的条目；Codex 检测现有 `notify` 冲突，可选择链式接入并在卸载时恢复原命令。

## 真实 hook 路由验证

在最终构建的 `YCode Native Dev.app` 和真实开发数据库上，用 bundle 内的 `ycode-notify` 调用实际 socket：

1. Claude `stop` 读取真实 JSONL transcript，连续发送两次；工具栏只出现 `关注 1`，证明相同事件去重。
2. Codex `permission_request` 发送 MCP 工具请求；同一会话的关注项更新为“需要处理”，摘要为 `codeagentswarm-tasks / check_active`。
3. 使用不存在的会话 ID 发送事件；收件箱仍只有原来的 1 项，没有串到其他会话。
4. 点击关注项后准确打开原会话，未读计数清零。
5. 应用重启后关注箱为空，说明临时运行态事件没有污染 SQLite。

## 安装与兼容边界

- Claude 重复安装不会重复追加；卸载只删除 `_ycode_managed` 条目，保留用户其他 hook 和未知设置。
- Codex 已有用户 `notify` 时，普通安装保持原文件不变并报告冲突；链式安装将原参数完整保存在 `--next`，卸载后逐值恢复。
- Codex 无冲突安装可重复执行，卸载只删除 YCode 标记的 `notify` 和 `PermissionRequest` 块。
- 两类配置首次修改前只备份一次；非法结构和缺失 helper 明确失败，不替换原文件。
- 本次可见检查只读取用户当前状态，没有安装或卸载用户真实 hook。

## 通知策略验证

- 自动测试覆盖总开关关闭、仅后台时前台静默、仅后台时后台投递、始终投递四种策略。
- 前台真实 hook 验证中没有系统横幅，关注收件箱仍更新，符合“仅在后台”。
- 隐藏 YCode 后发送真实 hook，关注收件箱仍收到该事件；通知权限已取得，设置界面显示“已允许”。
- 测试通知会轮询 macOS 已投递通知并核对自己的唯一 ID；最终界面显示“通知中心已接收”，不是只验证 API 调用没有抛错。
- 权限请求不影响 hook、关注箱或 Agent 进程；系统拒绝或通知中心未确认投递时，测试按钮会明确报错。

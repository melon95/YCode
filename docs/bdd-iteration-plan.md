# YCode CLI 工作台验收清单

更新：2026-10-18。对应[当前产品范围](ycode-feature-spec.md)，用于现有功能回归；不包含旧 Pi 统一基座的阶段排期、双模式门槛或功能编号。

## 用户流程

| 场景 | 验收结果 |
| --- | --- |
| 添加项目与配置 CLI | 项目目录正确；命令、参数、环境变量按已保存配置生效；开关可添加检测到的 CLI，停用保留配置、移除新建入口且不影响已有会话；缺少命令时给出明确错误 |
| 创建与恢复会话 | CLI 在对应项目中运行；恢复使用原始标识，不因打开窗口或切换项目重复创建；旧隔离会话不在主目录静默恢复 |
| 多项目与多会话 | 标签页、分屏和独立窗口正确显示对应会话，输入与通知不串项目 |
| 切换布局与焦点 | 已有终端进程保留，面板跟随焦点，布局切换不丢失输入或已有输出 |
| 停止、关闭与归档 | 各操作符合现有进程生命周期；界面状态与实际进程一致 |
| 文件查看与手动编辑 | 预览、固定、修改、保存及外部冲突处理正确，未保存内容不会被静默覆盖 |
| Git 审阅 | 工作区 diff 与文件一致，逐块暂存、提交和普通分支操作有明确结果 |
| 待办、Hook 与 MCP | 任务状态、会话关联、通知和待办工具对应正确项目 |
| 历史搜索与用量 | 来源与恢复标识正确；缺少记录时不虚构内容，不将本地 token 统计当作订阅余额 |
| 设置与更新 | 启停使用开关，独立操作使用带悬浮说明的图标，页面采用原生分组；集成开关与实际配置一致，冲突不覆盖，失败恢复原状态；设置保存及重启恢复一致；更新窗口、下载、签名校验和安装结果分别验证 |
| Skills 与 MCP 开关 | 只展示全局条目和完整来源路径，项目配置保持不变；CLI 切换不显示旧数据；开关写到全局配置，不移动技能文件，不覆盖外部修改；保留其他配置，写前备份，批准状态不被绕过，Claude 全局 MCP 只读 |

## 验证方式

- 自动化测试验证状态、参数、持久化、路径和确定性失败处理。
- 原生应用实测验证焦点、中文输入法、滚动、布局和多窗口行为。
- 实际 CLI 验证启动、确认、停止、恢复和历史；使用临时项目与隔离数据。
- 构建、签名、公证、CI 和实际发布单独记录。一次构建或原型检查不能代替运行验收。

Swift 回归入口：

```sh
swift test --package-path macos --build-system native --disable-sandbox
```

Hook 的配置与通知边界见[对接说明](agent-hook-integration-spec.md)，发布检查见[发布指南](macos-native/github-release.md)。原生迁移的既有里程碑证据见[历史记录索引](macos-native/README.md)。本清单不为延期功能设置自动恢复的排期，也不将未完成的能力标为已通过。

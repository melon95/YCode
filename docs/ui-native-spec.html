01

设计原则

这六条不是口号，是这一版所有删减的依据。后续任何一次加控件，都要先说清它不违反哪一条。

  1. 终端是画布，不是面板。 主区里除了 agent 终端什么都不放：标题行、PID、会话 ID、四个按钮全部移走。要操作有右键菜单；PID 与会话 ID 这类只在排障时才看的东西，进设置 › 关于与诊断。
  2. 动作跟着对象走。 没有「先选中再去底部找按钮」这种两步操作。暂存挂在文件行上，排序挂在待办行上，归档挂在会话行上。
  3. 状态只有两个半。 会话永远可以 resume，所以 exited / signaled / recoverable 不进界面，只留 运行中 / 等你 / 未在运行，同一个点在侧栏、窗格头、命令面板三处同源。
  4. 一个入口，第二入口是 ⌘K。 工具栏敢只留三组控件，是因为命令面板兜住了所有东西：会话、待办、历史全文、动作。
  5. 检查器装的是「当前工作区的切面」。 四个面板各自开关、可以并存，开着的堆在右栏里；面板之内不再有第二层分段控件。
  6. 即时生效，不留保存按钮。 macOS 的设置改完就写盘，主窗口立刻跟上；破坏性动作才给确认框。

03

统一性规约

同一件事在四个面板里有四种做法，是这一版之前最大的问题。下面十五条是全稿的横向约束——任何新面板先对照一遍，不符合就是 bug，不是风格差异。

#规约具体写法
01面板头只有一行，30 px左边一句摘要（「未暂存 · 3 个文件」「5 项未完成」），右边最多一个高频动作 + 一个 ellipsis.circle 菜单。不放标题重复 tab 名
02低频动作一律进 ⋯ 菜单302 px 放不下一排按钮。分支、Fetch/Pull/Push、刷新、检查点、显示已完成，全在 ⋯ 里
03行动作只在 hover 时出现常驻的是信息（+2 −0、副行），hover 时信息让位给动作（暂存／丢弃、⋯）。列表静止时可扫，不是一片按钮
04右键菜单是完整菜单行上能做的每件事都在右键里有一份，即使 hover 已经给了按钮。键盘/触控板用户不靠 hover
05破坏性动作红色 + 确认框role: .destructive，文案写清后果（「会停止正在运行的 Agent」「只删除 YCode 中的记录，不删除磁盘目录」）
06空状态两行：标题一句 + 说明一句标题陈述事实（「工作区是干净的」），说明讲下一步或机制。检查器里用 YCodeInspectorEmptyState，不用 ContentUnavailableView（它的大图标会把一句话撑成一屏）
07计数在分组标题上，不在面板顶部「进行中 3」「队列 5」自带计数，顶部不再放三个巨型数字
08徽标只回答「有没有」工具栏的面板开关上是 4 px 圆点，不是数字——具体数字面板头里已经有了，带数字的胶囊会把第四个 tab 挤进 » 溢出菜单
09选中态 = 强调色实底 + 白字侧栏会话行、⌘K 结果行共用；hover 态是 6% 前景色，二者不叠加
10焦点有两层标记画布焦点格：窗格头 16% 强调底 + 窗格四周 1 px 强调描边。只有画布有焦点概念
11输入即提交，回车即存待办输入行的 ＋ 与 ↵ 是提示不是按钮；重命名走系统 alert；搜索边打边过滤
12路径显示：粗名字 + 灰目录文件名在前，目录在后灰色，truncationMode(.head)。完整路径进 tooltip，不进正文
13时间用相对格式RelativeDateTimeFormatter(.short)，5 秒内写「刚刚」；只在状态有意义时写（队列里的待办不写副行）
14图标说过的事不再写一遍窗格头有 agent 图标就不写「Claude Code」，终端里已经在滚的动作不在窗格头再写一遍，文件行有类型图标就不写扩展名说明，状态点旁边不写「运行中」。文字留给图标表达不了的：活动、路径、计数
15面板顶部对齐所有检查器面板 frame(maxHeight:.infinity, alignment:.top)；不加的话内容比容器矮时整块会被垂直居中，头部上面空一大片

  1. 并排，不是替换。 已经在画布上就聚焦过去；还有空位就并排多开一格；满 4 格才替换当前焦点格。并排是 ycode 的核心差异，点第二个会话不该盖掉第一个。
  2. 点一行就已经在跑了。 进程不在就直接起（restartSession，resumingSessionIDs 防重复），过程发生在终端里——不给过场屏，也不给「接着跑」按钮。会话永远可以 resume，所以「没在跑」不值得占一屏。
  3. 点历史 = 点会话。 历史行走 resumeHistorySession，同样落到画布上；右键只有「重新打开」。
  4. 过滤 chip 是二选一。「全部 N」与「等你 N」，后者有值时带一个 warn 小点；计数与系统通知同源（attentionEvents）。
  5. 搜索是即时过滤。 只过滤会话名；要搜历史全文去 ⌘K。清空按钮在右侧 xmark.circle.fill。

检查器 · 面板栈

右栏不是「四选一的 tab」，是面板区：文件 · 变更 · 待办 · 终端各自独立开关。 开着的面板纵向堆在一列里，一列最多两张；开第三个就自动另起一列——面板区整体变宽，画布相应变窄。卡与卡、列与列之间留 8 的间距。全关就等于收起整个面板区。 面板区与画布同级：它从窗口顶部开始，上面没有横贯整窗的工具栏。

为什么从互斥 tab 改回并存：agent 跑起来的时候，要看的从来不是一样东西——盯着变更看它改了什么、同时瞄一眼待办还剩几条、旁边留个 shell 跑测试。互斥 tab 逼着人来回切，切一次就丢一次滚动位置。 数据模型里本来就是一个集合（openPanels: Set<YCodeWorkspacePanel>、showPanel / togglePanel），非原生版也是这么用的；原生版把它收成 selectInspectorTab 的互斥单选，是实现上的简化，不是设计决定。这一版改回来。

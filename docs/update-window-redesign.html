自绘更新窗口

现在的更新窗口是 Sparkle 自带的标准界面：英文、系统蓝按钮、图标是 bundle 里的图标，和应用的纸面浮卡风格以及应用内的语言设置都不一致。改成自绘：用 Sparkle 提供的自定义用户界面接口（SPUUserDriver）接管全部状态，更新的检查、校验和安装逻辑仍然是 Sparkle 的，只换界面。

要解决的问题

  • 文案是英文，且跟系统语言走，不跟应用里的语言设置走。
  • 主按钮是系统蓝，和珊瑚强调色冲突。
  • 标准窗口没有版本号对照，不知道是从哪个版本升到哪个。

成功标准

  • 所有状态的文案都跟应用内语言设置走（中 / 英）。
  • 配色、圆角、阴影与主窗口一致，亮暗两套都成立。
  • 全程键盘可操作；进度对读屏可读；出错时给得出原因和下一步。

1　流程与状态亮色

窗口固定宽 440pt，高度随内容变，位置居中偏上。图标用当前应用图标（棱角 Y），状态用图标右下角的小角标表达，不再靠换整张图。一个窗口走完全程，不会在状态之间弹出第二个窗口。

Sparkle 行为兼容

  • 版本、大小与更新说明链接，以及操作按钮按完整文字宽度自动换行；英文按钮不压缩、不裁切。
  • 每个阶段的选择只回复一次；进入下一阶段或关闭流程后，旧按钮回调失效。
  • 错误页的「重试」先确认错误，等 Sparkle 完整结束旧周期、允许重新检查后，再开始新检查。
  • 没有适合当前 macOS 或硬件的更新时，显示不可更新的原因；只有确认为已最新时才显示「已是最新版本」。
  • 仅提示信息的更新显示「了解详情」并打开发布者的信息页，不提供下载或安装操作。
  • 准备安装时选择「稍后」保留 Sparkle 的待安装状态；应用之后退出时，更新仍可能自动完成。

3　行为与取舍

主题设计理由
语言文案走应用内语言设置（中 / 英），随设置即时切换，不再看系统语言应用本身的文案就是这么管的；标准 Sparkle 窗口按系统语言，会出现应用是中文、更新窗口是英文
「下载并安装」发现新版本时一步到位，下载完成后停在 E「可以安装」，由用户决定何时重启重启会中断正在运行的 agent，不能替用户做这个决定
E 页的警告明确写出「正在运行的 agent 会话会被中断」，并给出「稍后」这是更新唯一有代价的一步，要在按下去之前说清
「查看更新内容」打开该版本的 GitHub Release 页，不在窗口里内嵌网页当前 appcast 里没有内嵌的更新说明；内嵌 WebView 会增加攻击面，也拖慢窗口
自动检查保持现状：启动后在后台静默检查，只在发现新版本时弹出窗口 B不改变更新策略，只换界面
出错文案区分网络错误、签名校验失败、磁盘权限三类；其余给通用提示并提供「复制错误详情」用户能照着做，也方便贴到 issue 里
签名与安装不变：下载、EdDSA 校验、替换、重启仍由 Sparkle 完成只自绘界面，不碰更新的安全边界

4　无障碍与键盘

键盘

  • ↩ 触发珊瑚色主按钮（图中带焦点环的那个），⎋ 触发「取消 / 稍后 / 关闭」。
  • Tab 在按钮之间循环；窗口出现时焦点默认落在主按钮上。
  • 下载阶段的 ⎋ / ⌘W 取消下载；解压与安装阶段的 ⌘W 只收起窗口，更新继续。

读屏与对比度

  • 进度条作为进度指示暴露数值，每 10% 播报一次，避免刷屏。
  • 状态变化（出现错误、可以安装）时播报标题。
  • 珊瑚主按钮白字对比度约 3:1，低于 4.5:1：按钮文字加粗到 600 并保持 12.5px 以上；如需严格达标，主按钮底色改用 #d93a2e（4.57:1），实现时以验证器为准。

5　待确认

问题建议理由
「下载并安装」是一步还是两步一步：按下即下载，下载完成后停在 E减少一次点击；真正有代价的重启仍由用户确认
是否保留「跳过此版本」保留Sparkle 原有能力，去掉会让想拒绝某版本的人只能一直被打扰
珊瑚按钮的对比度先用 #ff5a4e 与主窗口保持一致；验证后若不达标再整体加深品牌色一致比单个按钮的对比度更重要，但要有验证再定
窗口层级普通窗口，不置顶、不模态用户可以继续用应用，不被更新窗口挡住

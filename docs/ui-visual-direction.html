现状诊断为什么「没有高大上的感觉」

下面两张是当前开发版的实机截图。问题不在某个控件，而在整体没有「品牌」和「层次」。

当前：三栏终端画布
当前：新会话卡片

品牌断层

  • 图标和官网用珊瑚红 / 深墨 / 向日葵黄，App 里却是系统蓝 #0b63e5：焦点框、选中行、分段控件全是蓝色。
  • 浅色背景是纯白 #ffffff，没有色温，像默认模板。

没有层次

  • 侧栏、顶栏、窗格、终端全是同一层白，只靠 1px 灰线切开，满屏都是线。
  • 焦点窗格靠整条蓝色窗格头标出，颜色重、面积大，抢了终端内容的注意力。
  • 新会话卡片的 agent 按钮是四个灰块，没有 hover 反馈，也没有辅助信息。

三个方向同一个场景：侧栏 + 顶栏 + 三栏终端，焦点在中间窗格

三个方向都换成品牌色；区别在于窗格是「贴合」还是「浮起」，以及深色还是浅色优先。

A. 墨与珊瑚

深色优先 · 专业工具感

整窗压成官网的深墨色，终端再深一档，窗格之间用 1px 深紫缝隙分开。焦点只用一圈很淡的珊瑚色内描边，光标是向日葵黄。

  • 像 Warp、Linear 的深色版，长时间盯终端最舒服。
  • 风险：浅色模式要单独设计，气质会弱一些。

B. 纸面浮卡

浅色优先 · 与官网同源

底色换成官网那种带一点紫调的浅灰，侧栏和顶栏直接融进底色、不再画线；每个终端是一张圆角 11px 的白卡片，带柔和阴影浮在底上。焦点卡片是 1px 珊瑚描边加一圈淡珊瑚光晕。

  • 线少了一大半，层次靠「底 → 卡」两层表达。
  • 深色版同理：深墨底 + 略浅的墨色卡片（见下方）。
  • 代价：窗格之间多出 8px 间距，每个终端少约 1 列。

C. 原生精修

改动最小 · 最像系统应用

结构和现在一样，窗格仍然贴合铺满。只做三件事：侧栏改成系统半透明材质，强调色从蓝换成珊瑚，焦点从整条色块改成窗格顶部一条 2px 珊瑚线。

  • 最稳妥，一两天就能落地。
  • 但「高级感」的提升有限，本质还是满屏白和线。

方向 B：白卡片 + 柔和阴影，悬停项珊瑚描边，快捷键就近显示（示意 Claude Code 为悬停态）

推荐B 作为浅色，B 深色版作为深色

建议选 B「纸面浮卡」

  • 和品牌同源：底色、墨色、珊瑚、向日葵黄直接取自官网变量，图标、官网、App 三者是一套语言。
  • 线最少：侧栏与顶栏不再画分隔线，层次改由「底 → 浮卡」表达，这是高级感最主要的来源。
  • 焦点更克制：从整条蓝色窗格头改成珊瑚描边 + 光晕，内容区不被色块打断。
  • 和刚做的过渡动画天然契合：浮卡在切换布局时移动，比贴合的格子更像「一张张卡片在重新排列」。

实施记录2026-09-29 选定 B 并落地

与稿子不同的地方及原因

  • 强调色不用 Color.accentColor：macOS 上它读系统强调色，不跟随 .tint。新增 Color.ycodeAccent / ycodeAccentText，全 App 替换。
  • 侧栏保留品牌底色：macOS 26 把侧栏放进系统玻璃面板，玻璃是偏冷的灰，和紫调底色对不上，所以仍铺 #efeef4。侧栏右缘那条细影是系统玻璃自带的，未去掉。
  • 窗格描边画在 AppKit 裁切层上：画在 SwiftUI 里会被拍进过渡快照，移动途中描边只围住一部分；图层 border 始终跟随动画中的边界。
  • 单色 agent 图标默认用官网的 agent 蓝 #2f6fed：原来跟随系统蓝，改成珊瑚后会和 Claude 的橙色撞色。
  • 新会话卡片没有加 ⌘1–⌘4：稿子里的快捷键只是示意，App 目前没有这组快捷键，不为视觉凭空加功能。
  • 面板区列首卡头从 44 降到 36：卡片顶上让出 8px 缝，卡头下沿仍与画布顶栏下沿对齐。
